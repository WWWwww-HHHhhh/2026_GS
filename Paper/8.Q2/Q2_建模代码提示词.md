## P1 因果预测与经验场景库

【提示词】

你是一名数学建模代码工程师。为 C 题问题二实现“因果负荷/光伏预测 + 整日残差块联合场景生成”。唯一依据：总纲 `$MD` 第 4.2、4.4、4.8 节；全局铁律见本文档第 2 节。

创建两个文件，放在 `$Q2CODE\Model_Establishment+Solution`：

### 1) `forecast.py`

- 输入：`q2_data_prepare.py` 保存的 `q2_dataset.pkl`。
- 目标：对每个“决策日 i”（2025-01-02 起；2025-01-01 为无历史预热日），在当天 0:00 分别预测负荷 `Lhat[i,t]` 与光伏 `Ghat[i,t]`（kWh 电量），t=1..144，必须分别建模，禁止只预测净负荷（总纲 4.2 第 3 条）。
- 特征（只允许历史构成）：时刻索引 t(1..144)、星期(0..6)、年内日序 doy、前 1 天同 t 实际值、前 7 天同 t 实际值、仅由历史（不含当天）计算的同 t 滚动均值与滚动标准差（窗口 7 天，缺失时用可得的过去值并记录）。对负荷与光伏分别构造。
- 三个候选预测器：a) 季节朴素（同 t 历史中位数）；b) 岭回归（正则化线性）；c) sklearn 的 HistGradientBoostingRegressor（浅树，如 max_depth=3、learning_rate=0.1、n_estimators≤200）。任何候选都只用 ≤i−1 天的数据训练。
- 每日扩展窗口验证（选择“当时可用”的预测器，总纲 4.2 第 3 条）：预测第 i 天时，用 ≤i−2 天训练、在 i−1 天上做一步预测评估，以 WAPE（Σ|误差|/Σ实际）选最优候选；再用 ≤i−1 天重训并预测第 i 天。记录每天选中的模型与验证 WAPE。
- 特殊处理：2025-01-01 无历史，预测输出全 0（仅作预热，不进入残差库、不进入任何统计）；2025-01 整月为预热期，其预测、残差、结算只用于滚动机器与残差库积累，不进入论文报告（总纲 4.2 第 1 条）。
- 输出 `Results\Tables\forecast_validation.csv`：每天每序列（负荷/光伏）的选中模型、验证 WAPE；并按月汇总 MAE/WAPE（含样本量）。
- 预测用随机种子固定（如 20260101），保证复现。

### 2) `scenarios.py`

- 残差定义：res = 实际 − 预测（负荷、光伏各自）。
- 整日残差块库：第 i 天结束后，把当天的 144 维负荷残差与 144 维光伏残差作为一个“同日联合残差块”追加进库（2025-01-01 除外）。

  - `L_scen[m,t] = Lhat[i,t] + load_res_block[m,t]`，`G_scen[m,t] = Ghat[i,t] + pv_res_block[m,t]`；

## P2 两阶段随机 LP + CVaR 优化器

【提示词】

你是一名数学建模与优化代码工程师。请实现问题二的“经验场景两阶段随机 LP + CVaR”单日优化器。唯一依据：总纲 `$MD` 第 4.1、4.4、4.5、4.6 节与第 2.3 节公共物理约束；全局铁律见本文档第 2 节。

创建 `$Q2CODE\Model_Establishment+Solution\optimizer.py`，函数签名如 `solve_day2(price, scenarios, s0, params) -> plan`。

模型必须严格按以下公式实现（全部线性，不得出现整数/非线性项）：

**输入参数（已知量）**：电价 `π[t]`（144 维，元/kWh）；M=20 个场景 `(L[m,t], G[m,t])` 与概率 p[m]=1/20；期初 SOC `s0`；`alpha=0.90`、`beta`（默认 0.5，灵敏度见 P3/P4）、`eps`（如 1e-4，仅作充放电小量惩罚）、`kappa2 = kappa2_base`（来自 P0 表）；`eta_c=eta_r=0.9`、`s_min=1200`、`s_max=10800`、`cap=833.3333`、`s_ref = s0`。

**变量**：
- 第一阶段（跨场景共享，非预期性）：`x[t] ≥ 0` 计划购电(kWh)、`c[t] ≥ 0` 充电(kWh)、`r[t] ≥ 0` 放电(kWh)、`s[t]` 状态 SOC（t=0..144，s[0]=s0）、`xi_p, xi_m ≥ 0` 终端软偏差。
- 第二阶段（每个场景 m）：`y[m,t] ∈ [0, x[t]]` 实际提取计划电、`u[m,t] = x[t] − y[m,t]` 未提取计划电、`e[m,t] ≥ 0` 紧急购电、`g[m,t] ∈ [0, G[m,t]]` 实际利用光伏、`w[m,t] = G[m,t] − g[m,t]` 弃光、`q[m] ≥ 0` CVaR 辅助变量、`zeta` 自由变量（CVaR 分位点）。

**约束**（每条写注释对应总纲 4.6 的表格行）：
- 场景电量平衡（总纲 2.3 公共式）：`y[m,t] + e[m,t] + g[m,t] + r[t] = L[m,t] + c[t]`（计划电不够时由 5 倍价紧急购电补足；光伏优先被利用由目标隐含）。
- `u[m,t] = x[t] − y[m,t]`；`w[m,t] = G[m,t] − g[m,t]`。
- SOC 递推（总纲 2.3）：`s[t] = s[t−1] + eta_c*c[t] − r[t]/eta_r`（共享计划递推，不随场景分裂）。
- `s_min ≤ s[t] ≤ s_max`；`0 ≤ c[t] ≤ cap`；`0 ≤ r[t] ≤ cap`。
- 软终端（总纲 4.6）：`s[144] − s_ref = xi_p − xi_m`（初版 s_ref = s0）。
- CVaR 线性化（总纲 4.5）：`C[m] = Σ_t π[t]*x[t] + 5*Σ_t π[t]*e[m,t]`；`q[m] ≥ C[m] − zeta`；`q[m] ≥ 0`。

**目标**（总纲 4.5）：
`min J = (1−beta)*Σ_m p[m]*C[m] + beta*( zeta + (1/(1−alpha))*Σ_m p[m]*q[m] ) + eps*Σ_t(c[t]+r[t]) + kappa2*(xi_p+xi_m)`。

**实现**：优先 PuLP + CBC/HiGHS；若环境无 PuLP，用 scipy.optimize.linprog(HiGHS) 自建矩阵。变量数量级约 1+144*4+M*144*5+M+2（M=20 时约 15k 变量）；若数值稳定性不足，允许对目标系数整体做等比例缩放并在日志记录缩放因子，约束不得放宽。

返回 plan：x、c、r、s、xi_p、xi_m、目标值、期望成本 E[C]、CVaR、每个场景的 y/e/g/w/u/q。

验收：随机一天跑通后打印平衡残差最大值（应 ≤ 1e-6 量级）、SOC 是否越界、第一阶段变量是否只有一个版本（共享）。
禁止：把 c、r、s 写成场景相关变量（总纲 4.8，违反非预期性）；给目标加入任何非总纲项；报告费用包含 eps/kappa2 项。

## P3 事后结算与滚动推进

【提示词】

你是一名数学建模代码工程师。请实现问题二“当天真实数据事后结算 + 跨日滚动”。唯一依据：总纲 `$MD` 第 4.2、4.5、4.8 节；全局铁律见本文档第 2 节。

创建两个文件，放在 `$Q2CODE\Model_Establishment+Solution`：

### 1) `settlement.py`

- 输入：某日 0:00 已锁定的计划（x、c、r）、当天真实负荷 L 与真实光伏 G（结算时点之后才可读取）、电价 π。
- 结算子问题（线性）：给定固定 x、c、r，求实际提取 y、紧急购电 e、光伏利用 g、弃光 w，目标 `min Σ_t 5*π[t]*e[t]`，约束同 P2 的场景平衡式（用真实 L、G 代替场景值）：`y+e+g+r = L+c`，`0≤y≤x`，`0≤g≤G`，`w=G−g`，`e≥0`。
- 实际 SOC 递推（总纲 2.3）：`s_actual[t] = s_actual[t−1] + 0.9*c[t] − r[t]/0.9`，`s_actual[0] = 当日实际期初 SOC`；记录是否越界（只记录不修改）。

- 当日评价量：紧急购电率（紧急电量/负荷总量）、未提取计划比例（Σu/Σx）、弃光率（Σw/ΣG）、SOC 越界数。
