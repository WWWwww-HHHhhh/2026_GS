## 4. 决策时序与信息集（因果，不可变）

1. 每个自然日 **只在 0:00 决策一次**：得到全日计划 `x[0:144]`、充放电 `c[0:144]`、`r[0:144]`。
2. 决策日 i 允许使用的信息：

## 5. 模型结构（与 Q2 逐项对应）

**变量**（沿用 Q2 命名）：
- 第一阶段（跨场景共享，非预期性）：`x_t` 计划购电量、`c_t` 充电、`r_t` 放电、`s_t` 储电量、`ξ⁺/ξ⁻` 终端松弛。
- 第二阶段（逐场景 m 独立）：`y^m_t` 实际提取的计划电量、`e^m_t` 紧急购电量、`g^m_t` 光伏利用、`w^m_t` 弃光、`spill^m_t` 供给过剩弃电。

**约束**（与 Q2 完全相同）：
- 电量平衡：`y + e + g + r = L + c`（每时段每场景）
- 光伏拆分：`g + w = G`，`0 ≤ g ≤ G`
- 提取上限：`y ≤ x`（计划量是上限而非义务；未提取部分单独统计）
- 储能：SOC 递推、`s ∈ [1200, 10800]`、`c, r ∈ [0, 833.3333]`
- 终端：软约束，偏差 `|s_144 − s_0|` 由 `κ`（由 Q1 储能边际价值中位数标定）惩罚
- 非负性

**目标函数**（Q4-2 的**唯一**结构性改动：价格进入场景）：
```
min  (1 − β)·E_ω[C^ω] + β·CVaR_α(C^ω) + κ·|s_end − s_0|
C^ω = Σ_t λ^ω_t · x_t      （计划购电费，按交易时刻实际电价计，付了不管是否提取）
    + Σ_t 5·λ^ω_t · e^ω_t  （紧急购电费，5 倍交易时刻电价）
```
- Q2 中 `λ` 为附件1 的确定序列；**Q4-2 中 `λ^ω` 为逐场景的波动电价**。
- 求解用 `scipy.optimize.linprog`（HiGHS）+ 稀疏矩阵装配，CVaR 线性化（`β/α` 权重 + 辅助变量）。
- 惩罚项 `eps` 与终端罚项只用于求解，**报告的真实费用不含它们**。

## 6. 结算规则（与 Q2 完全相同，逐时段顺序执行）

对每个时段 t（按自然日顺序）：
```
demand = L[t] + c[t] − r[t]
spill[t] = max(0, −demand)          # 日前固定放电造成的供给过剩，记为弃电
需要供给 = max(0, demand)
g[t] = min(G[t], 需要供给)
剩余 = 需要供给 − g[t]
y[t] = min(x[t], 剩余)              # 提取不超过计划
e[t] = max(0, 剩余 − y[t])
```
- 计划购电费 `C_plan = Σ_t λ_t · x_t`（λ 为当日实际电价）
- 紧急购电费 `C_emg = Σ_t 5·λ_t · e_t`
- 全天计划购电量 `X_d = Σ_{t=0}^{143} x_t`（**含 x[0]**）
- 统计指标：紧急购电率、未提取计划比例、弃光率、SOC 越界数

## 7. result4-2.xlsx 导出（与 result2 同构）

**计划购电量工作表**，令模板行日期为 d：
```
行 d 前 143 个计划格 ← x_d[1:144]        （标签 0:10-0:20 … 23:50-0:00+1）
行 d 最后一个计划格  ← x_{d+1}[0]        （标签 0:00-0:10+1）
最后一行(2025-12-31)的最后计划格 ← 空，且【只有】这一格为空
```
- 「全天购电量」列 = 自然日 `Σ x_d[0:144]`；「全天购电费」列 = `Σ_t λ_{d,t} · x_{d,t}`。
- 报告期首日 2025-02-01 的 `x[0]` 不出现在任何行，但仍参与当日模型、执行、全天量、费用、SOC 与平衡。
- 因此普通行的 144 个可见格之和**一般不等于**全天购电量，差值恒为 `x_{d+1}[0] − x_d[0]`（末行为 `−x_d[0]`）。这是模板结构，不是错误。
- **禁止**为凑"行内和 = 全天量"而改成同行直填。

**充放电量工作表**（自然日口径，不做跨行移位）：六段为
`c[0:24]→0:00-4:00`、`c[24:48]→4:00-8:00`、`c[48:72]→8:00-12:00`、`c[72:96]→12:00-16:00`、`c[96:120]→16:00-20:00`、`c[120:144]→20:00-24:00`；放电同分组；另填 `0:00` 与 `24:00` 储电量。

**紧急购电量工作表**（自然日口径）：按 `period_start-period_end` 输出，`e[0]→0:00-0:10`、`e[5]→0:50-1:00`、`e[143]→23:50-24:00`；**相邻连续正值合并为一个时间段事件**，按事件扩行。
