# 队员使用说明

[返回项目首页](../README.md)

## 使用环境与要求

- 安装 Git 和 VS Code；推送到本仓库需要 GitHub 账号及仓库写入权限。
- 论文编译需要 TeX Live 中的 XeLaTeX，以及 VS Code 的 LaTeX Workshop 扩展。当前模板已在 TeX Live 2025 下验证编译。
- 打开仓库根文件夹，保留 `.vscode` 中的项目配置，以使用保存后自动编译功能。
- `.tex` 文件使用 UTF-8 编码。各队员使用相对路径引用文件，避免写入自己的盘符路径。
- 建模程序所需环境和依赖按实际代码补充，不能将论文编译环境视为程序运行环境。

## 常用文件入口

- [论文主文件](main.tex)：编译整篇论文。
- [标题与摘要](1.Abstract/content.tex)：修改标题、摘要与关键词。
- [排版设置](layout.tex)：统一设置字号和间距。
- [建模代码](../All_Code/)：数据处理、模型求解和结果输出。

## 首次使用与论文预览

1. 在 VS Code 克隆仓库，打开包含 README.md、Paper 和 All_Code 的仓库根文件夹。
2. 安装 TeX Live（包含 XeLaTeX）和 VS Code 的 LaTeX Workshop 扩展。仓库已经配置保存后自动编译。
3. 打开 `Paper/main.tex`，按 **Ctrl+Alt+B** 编译，再按 **Ctrl+Alt+V** 打开完整论文预览；也可以点击左侧 TEX 面板的编译和预览按钮。
4. 编辑负责的板块，按 **Ctrl+S** 保存。编译成功后，已打开的 PDF 预览自动刷新。

完整论文输出为 `Paper/Paper_Compilation/main.pdf`。编译失败时，PDF 保留上一次成功的版本，请查看 LaTeX Workshop 日志。

## 各板块写什么

在 `Paper/` 下，通常编辑对应文件夹的 `content.tex`：

- `1.Abstract/`：论文标题、摘要与关键词。
- `2.Problem_Background_and_Restatement/`：问题背景与问题重述。
- `3.Problem_Analysis/`：各问分析与整体思路。
- `4.Model_Assumptions/`：模型假设及理由。
- `5.Symbol_Description/`：符号含义与单位。
- `6.Data_Preprocessing/`：数据来源、清洗及特征分析。
- `7.Q1/`：问题一。
- `8.Q2/`：问题二。
- `9.Q3/`：问题三。
- `10.Q4/`：问题四。
- `11.Model_Evaluation/`：在 `content.tex` 中统一写模型的优点、缺点和改进；`conclusion.tex` 单独写全文结论。
- `12.References/`：参考文献。
- `13.Appendix(fulu)/`：正文中保留支撑材料清单，`Intermediate_Calculation_Results/` 放补充计算结果；完整代码通过独立 ZIP 包提交，不嵌入论文。
- `Paper_Compilation/`：自动生成的完整 PDF 和编译临时文件，不在这里写正文。

每问只需编辑一个 `content.tex`，在文件内依次写建模思路与变量定义、模型建立、求解方法、结果分析、模型检验。小标题已保留，可按实际内容调整。

## 标题、正文和排版

- `Paper/main.tex`：主文件，汇总各板块并控制顺序。
- `Paper/1.Abstract/content.tex`：在开头的 `\newcommand{\papertitle}{...}` 中修改标题，下面接着写摘要与关键词。标题和摘要已合并，不再使用 metadata.tex。
- `Paper/layout.tex`：宏包和统一排版。首页论文标题为三号黑体（16pt），摘要标题为四号黑体（14pt），正文沿用小四号；标题字号与间距在 `\makepaperheading` 中设置。
- 各板块 `content.tex`：日常填写正文；每问只需编辑一个文件。

保留子文件首行的 `% !TeX root = ...`。新增 `.tex` 文件需通过 `\input{...}` 引入，单独放进文件夹不会进入全文。图片路径以 `Paper/` 为基准，例如 `../All_Code/Q1/Results/Pictures/result.png`。参考文献在 `12.References/content.tex` 中定义，正文通过 `\cite{ref1}` 引用。

## 四问改成三问

删除或注释 `Paper/main.tex` 中的 `\input{10.Q4/content.tex}`，再删除摘要、问题重述和问题分析中的第四问文字。问题四文件夹可以保留备用；不要仅删除文件夹而留下主文件引用。

## 代码与输出

`All_Code/` 按公共处理和各问任务划分：

- `Data_preprocessing/`：公共数据预处理；`Data_clean/` 为数据清洗，`Data_transformation/` 为数据转换，`EDA/` 为探索性数据分析。
- `Q1/` 至 `Q4/`：各问代码与输出。
- `Model_verification/`：模型检验代码。

各问中，`Data_processing/` 为本问数据处理，`Model_constraints/` 为约束相关内容，`Model_Establishment+Solution/` 为建模与求解，`Pictures/` 为图片，`Tables/` 为表格。建模求解目录下的 `Variables/`、`Formulas/`、`Model_flow/`、`Results/` 分别对应变量、公式、模型流程和结果。

新增程序时简要注明输入数据、运行方法和输出位置，路径尽量使用相对路径，方便队友复现。代码生成的图片或结果需要在论文中引用或填写，不会自动变成论文正文。

## Notes 与论文附录

`Notes/` 用于 AI 使用说明、使用记录和队内备忘，不会自动编译进论文。正式论文附录放在 `Paper/13.Appendix(fulu)/`；实际运行代码放在 `All_Code/`，最终整理为独立 ZIP 包提交。压缩包内附运行说明、环境依赖和必要的数据或数据获取说明；论文附录仅列出压缩包名称及内容用途，不粘贴完整代码。需要提交的 AI 使用材料按比赛要求整理到附录或独立文件。

## GitHub 协作（不用终端）

1. **开始写之前：** 在 VS Code 左侧「源代码管理 → … → 拉取」获取队友更新；有未完成的本地修改时先保存并妥善提交。
2. **分工写作：** 各自修改负责的板块，尽量避免同时修改同一个文件；排版和主文件修改先在队内沟通。
3. **完成一小部分：** 保存并检查结果，在「源代码管理」里检查改动，点击文件旁的 `+` 暂存，填写说明后提交，例如「补充问题二模型约束」。
4. **分享给队友：** 提交后通过「… → 推送」上传到 GitHub。若提示远端有新提交，先拉取并处理冲突，再推送。

**保存、提交、推送是三件事：** 保存更新本地文件和论文；提交记录本地版本；推送后队友才能从 GitHub 拉到更新。推送需要仓库写入权限。

编译输出默认不纳入 Git，队员在各自电脑生成 PDF。比赛最终版可统一整理后通过 GitHub Release 发布。

## 赛后项目整理

当前仓库是协作模板。若后续作为课程、简历或作品集项目，建议补齐：

- **项目介绍：** 实际赛题、研究背景、解决的问题与核心方法。
- **成果展示：** 关键结果、对比指标、代表性图表及最终论文。
- **可复现说明：** 环境版本、依赖文件、数据来源、运行入口与执行顺序。
- **团队贡献：** 各成员负责的建模、编程、写作与验证工作。
- **版本发布：** 通过 Release 保存最终论文和可运行代码，为重要版本添加标签。
- **仓库信息：** 完善 GitHub 的简介与 Topics；根据实际使用条件选择许可证。

公开展示前核对数据和材料的公开范围，尤其是 `Else/Participant_list/` 中的登记资料。若个人信息曾被提交，单独删除当前文件不会清除 Git 历史，应另行处理。

模板中的提示文字、示例公式和参考文献需替换成实际研究内容。
