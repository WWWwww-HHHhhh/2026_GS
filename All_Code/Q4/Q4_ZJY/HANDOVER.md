## 3. 关键建模决策（论文必须写明）

### 3.1 电价信息假设 ⭐ 最重要

附件 4 = 2025 全年每天 144 个 10 分钟时段的**实际电价**（365×144）。

**本文不假设当天 144 个未来电价在 0:00 已知。** 题面仅说明电价实时波动，因此每个决策时点使用因果预测和严格早于目标日的历史价格残差场景，目标日实价仅用于已执行区间结算。

- 附件4均值与附件1接近，只能作为数据一致性检查，不能推出目标日电价已在0:00公布
- 后果：电价进入逐场景随机目标，实际价格只在结算时使用，避免未来信息泄露
- **必须在论文里明写这一假设**——这是评委必抓的点（Q3 公开评阅要点里也点名过"0:00 是否已知全天电价"）
- 价格预测文件由 Q4-2 生成，元数据记录其哈希，校验器还会检查场景来源日期

### 3.2 其余全部沿用 Q3（不要重新论证）

| 组件 | 值 / 来源 |
|---|---|
| 决策结构 | 非预期性两阶段随机 LP（第一阶段全场景共享，recourse 按场景） |
| 场景 | M=30，最近 30 历史日成对抽负荷/光伏残差，同（日,时点）各策略同种子 |
| 风险 | CVaR，α=0.9，β=0.2，κ₂=0.5317 |
| 结算 | 主口径 `p·A + 0.5p·|A−Q|`（相对 0:00 一次性结算，不重复加收） |
| 预报 | 附件 3 整点预报线性插值到 10 分钟（1 月历史期选定，非正式期） |
| 采纳策略 | **Sall**（本次因果回测实际费用最低，和 S6_12 差异很小） |
| 初始/终端 SOC | 6000 kWh，日末回到日初值 |

**Q3 已就此写过完整论证（含结算口径两种解释的敏感性）**，Q4 正文只需写"沿用问题三"并点出差异（仅电价），不要重写一遍。

### 4.1 波动电价六策略（2025-02-01 ~ 12-31，334 天）

| 策略 | 总费用/元 | 其中紧急购电/元 | 紧急电量/kWh | 弃光/kWh |

| Sall | 15,138,138.52 | 609,760.86 | 153,291.8 | 1,632,017.7 |

### 4.2 波动 vs 固定电价

| 策略 | 固定电价/元 | 波动电价/元 | 差/元 |
|---|---:|---:|---:|
| S0 | 14,861,386 | 15,499,059 | +637,673 |
| S6 | 14,686,100 | 15,314,156 | +628,056 |
| S12 | 14,655,736 | 15,278,434 | +622,699 |
| S18 | 14,875,908 | 15,507,243 | +631,335 |
| S6_12 | 14,517,697 | **15,137,157** | +619,460 |
| Sall | **14,517,640** | 15,138,139 | +620,498 |

### 4.3 三条结论（论文卖点）

1. **波动电价使全年费用普遍上升约 62 万元（≈ +4.2%）** —— 日内峰谷差大，高价时段购电更贵
2. **滚动更新的价值在波动电价下反而增大**：S0 减最优策略的节省，固定电价 343,746 元 → 波动电价 **361,902 元**（= 15,499,059.00 − 15,137,156.79）
   > ⚠ README 里写的 360,920 是拿 Sall 算的；用真正的最优策略 S6_12 应为 **361,902**，论文请用后者
3. **最优策略由 Sall 变为 S6_12**：波动电价下 18 点更新从"无价值"变成"略微有害"（Sall 比 S6_12 贵 981.73 元，占 0.006%）。**"引入 6/12 点、不引入 18 点"的结论在两种电价下一致**，这是很强的稳健性论据

## 6. ⚠ 陷阱清单（这份最值钱，开工前先读）

| # | 坑 | 说明 / 规避 |
|---|---|---|
| 1 | **`validate_q4.py` 必须替换电价** | 它是 `validate_q3.py` 的副本。Q3 版用固定电价校验，不改会报 `price max deviation 0.50`。改动点：`data=SourceData.load_verified()` 之后加 `data.price=load_q4_price()` |
| 2 | **`sys.path` 必须插在 `from __future__` 之后** | Python 要求 `from __future__` 是首个语句，插它前面直接 SyntaxError（踩过） |
| 3 | **路径基准 `parents[3]` 不是 `parents[4]`** | `Path(__file__).parent` 的 parents 比 `Path(__file__).parents` 少一级。写错会定位到 `MathModel` 而非 `2026_GS`（踩过两次） |
| 4 | **紧急事件数曾硬编码** | 现按 intervals 动态重算，`validate_result4_workbook.py --strategy` 会随采纳策略检查事件数 |
| 5 | **`result3_payload.json` 是 Q4 的载荷** | 名字沿用了 Q3（复制时没改名），别当成 Q3 产物误删或误用 |
| 6 | **`prepare_result4.py` 默认 S6_12** | 若要改用 Sall 导出，需同时改 `prepare_result4.py` 的 `--strategy` 和 `validate_result4_workbook.py` 里的 `S6_12` 路径（两处） |
| 7 | **Q4 依赖 Q3，但 Q3 不依赖 Q4** | 改 Q3 会牵动 Q4 结果。若要动 Q3（如调参数），务必重跑 Q3 与 Q4 两边并对账 |
| 8 | **附件 4 时间标签是右端点** | 与附件 1/2 一致，勿当成左端点（否则整体错一个时段） |
